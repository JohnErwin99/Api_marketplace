Runtime security

Bearer token handling

OAuth 2.0 client credentials is the default pattern for server-to-server consumers.

Request
Authorization: Bearer <access_token>
Content-Type: application/json
X-Correlation-ID: 8f3a…
01

Validate every request

Verify issuer, audience, signature, expiry, client identity, and required scope.

02

Keep tokens short-lived

Use secure secret storage, rotation, and immediate revocation when ownership or risk changes.

03

Enforce least privilege

Authorize the specific operation and customer boundary—not merely a valid token.

04

Never expose secrets

Do not place tokens in URLs, logs, tickets, source code, browser storage, or screenshots.

Request→Token validation→Scope + customer authorization→API operation→Audit event

Protect

  • Make records tamper-evident and time-synchronized
  • Define retention by legal, security, and business needs
  • Alert on repeated denial, abnormal volume, and privileged actions
Never log: bearer tokens, client secrets, passwords, authorization codes, full payment data, or unnecessary personal data.
